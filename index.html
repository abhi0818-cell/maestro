What every button in this admin panel actually does, what it writes, and any gotchas worth knowing before you click. Built from a full code trace — update this if behavior changes.
Tournament
Connect to database
Requires both URL and anon key. Loads teams, tournaments, contests, matches, scores, and tries to restore your last saved XI. Each loader fails silently on its own (console-only warning) — a bad connection can leave parts of the UI half-populated with no single clear error.
⚠️ Once connected, the form collapses to "✓ Connected"; click Change to reconnect. Re-connecting discards any unsaved scoring-rule edits.
Active Tournament picker
Pure context switch, writes nothing. Reloads matches, scoring rules, contests for the newly selected tournament.
⚠️ Switches silently even with unsaved scoring-rule edits — they're discarded, no warning.
Active/Inactive toggle (per tournament)
Sets tournaments.is_active — controls whether it shows in the mobile lobby. Multiple tournaments can be active at once. Reversible.
Max overseas in XI
Sets tournaments.max_overseas_in_xi. If this is the active tournament, XI-picking validation updates immediately, no reload needed.
⚠️ Client validates 0–11, but there's no DB-level check — only RLS, which allows any value if the client is bypassed.
Non-overseas label
Cosmetic only — sets tournaments.domestic_label, shown on the pool's filter chip. Doesn't touch overseas flags or the cap itself.
Scraper toggle
Sets tournaments.scraper_enabled — controls whether the server-side scraper cron runs for this tournament's matches.
Dot ball scoring toggle
Sets tournaments.dot_ball_enabled. If active tournament, the scoring rules grid re-renders immediately to show/hide the dot-ball row.
⚠️ OFF is enforced server-side too — dot-ball scoring is forced to 0 at actual scoring time regardless of any saved weight, not just hidden in the UI.
Player photos toggle
Sets tournaments.show_player_photos. Kill switch for the jersey photo feature (migration_v45/v46) — OFF makes the app always render the plain jersey icon, regardless of whether players.photo_url is populated. Defaults ON.
CricAPI Series ID
Sets tournaments.cricapi_series_id. If active tournament, also mirrors into Schedule tab's sync field.
+ New Tournament
Only name is required. Creates the row and switches to it immediately as the new active tournament — no confirmation.
⚠️ No duplicate-name check anywhere — creating the same name twice silently succeeds as two separate rows.
Scoring Rules — Save
Merges the active format tab's rules into tournaments.scoring_rules (JSONB) — other formats untouched. No confirmation.
⚠️ The "locked once started" rule is enforced client-side only (checks if any match is in_progress/completed) — there's no equivalent server-side check, so a direct API call could still change rules after a tournament has started.
Scoring Rules — Reset to defaults
Deletes the active format's key from the rules JSONB, reverting to built-in defaults.
Asks for confirmation first — the only confirm() in this tab.
Schedule
Sync from CricAPI
Pulls fixtures + start times from CricAPI for the active tournament (using the Series ID + sync filter). Creates/updates match rows; doesn't touch scores.
Finalize completed
Batch-finalizes every completed match missing saved stats — fetches (or reuses cached) scorecards, saves fantasy points. Shows progress + a grouped failure panel.
Inline row edits
Match number, teams, format, start time, match type, data source override, lock time — all save on blur.
🌧 Delay toggle
Sets status='delayed'. This changes which time field the lock cron reads: normally it locks based on start_time; once delayed, it switches to lock_time instead. Also removes Finalize/Recalc/Poll/Scrape from the row (no longer "in play").
⚠️ Un-delaying just resets status to 'scheduled' — it does not restore whatever the real status actually was. The next sync/poll corrects it. Also: a delayed match with no fresh lock_time drops out of the home screen's "next match" countdown entirely on both web and mobile — set a new lock_time (not just toggle delayed) to keep it showing correctly.
Finalize / Recalc (row)
Same as the toolbar Finalize, scoped to one match. Recalc re-parses the already-cached scorecard without a new API call — useful after a scoring-rule change.
🥎 Fielding (manual credit)
Freeform: any player, any category (catch/stumping/run-out/bowled/LBW bonus), regardless of whether anything was auto-detected. Tagged source='scraper_manual' so a later re-scrape can't silently overwrite it. This is the same underlying function Review tab's Fielding Issues "Credit" button calls — not a separate implementation.
↩ Revert to Live
For a match wrongly marked completed — flips it back to in_progress so Poll/Scrape can run again. Does not delete already-saved stats; they get overwritten by the next Poll/Scrape/Recalc.
Asks for confirmation.
🔓 Revert Lock
Deletes locked Season-Long XI rows for this match so users can re-pick. Only affects user_match_xi — nothing else.
⚠️ Only appears once status='delayed' — clicking it on a non-delayed match with a past start_time would be self-defeating, since the lock cron (runs every minute) would just re-lock everyone again immediately. Also: what the user sees afterward is their current live draft, not a restored copy of what was actually locked — if they kept editing during the delay window (possible once delayed, since the match re-opens as an editable target), that's what comes back, not the original locked picks. And: no transfer refund happens — if a transfer was spent making the now-deleted pick, it stays counted against their budget with no automatic reversal.
🔓 Revert Daily Lock
Only clears the visible "Locked" badge on daily teams — cosmetic. Real gating is lock_time via RLS, so editing doesn't actually reopen unless lock_time is also pushed forward.
Asks for confirmation; the dialog itself explains it's badge-only.
📡 Poll / 🕷 Scrape (row)
Manually triggers the same server-side poll-cricapi/scrape-scorecard edge functions the cron runs, scoped to one match. Scrape also auto-derives fielding credit where possible, flagging anything ambiguous into Review's Fielding Issues queue.
Same edge functions the mobile app's own admin screen triggers independently — two separate UIs, same backend calls.
× Delete (row)
Deletes the match row outright.
⚠️ No confirmation dialog — the only destructive action in this tab that doesn't ask first.
Teams
Add / remove alias
CricAPI→internal team code mappings. Stored client-side only (in-memory + localStorage) — not a database table. Re-adding an existing code silently overwrites its target.
Apply to existing matches
The only alias action that touches the database — updates matches.home_team_id/away_team_id for the active tournament, per alias pair. Same function as Schedule's old "Fix team codes" button (now removed as a duplicate).
Add team
Code auto-suggested (first free T1, T2…), editable, max 6 chars. Client-side duplicate-code check before insert.
Inline edit
Name and both colors are editable, save on change.
Team code (id) is not editable after creation — it's the primary key.
Delete team
Confirmation dialog mentions players only.
⚠️ Blocked outright if any player still belongs to the team (foreign-key restrict, friendly error shown). But matches referencing the team are NOT a guard — deleting succeeds and silently sets those matches' home/away team to null, with no warning in the confirmation dialog.
Players
Search
Client-side only, matches name or team — never touches the database.
Import CSV
Validates every row before sending anything: required name, known team, valid role, non-negative credits.
⚠️ Collision guard: a blank id whose name matches an existing player (under a different id) is flagged as an error, not silently turned into a new duplicate player — this was a real bug that's since been fixed. A typed id that belongs to a different-named player is also blocked. Only rows that pass validation are ever sent; on a failed batch partway through, earlier successful batches of 50 are NOT rolled back — a large import can leave a true partial commit.
Clone from another tournament
Copies team assignment, credits, and active flag from the source tournament's roster into the target — reuses existing global player IDs, no new player rows created, only new per-tournament roster rows.
If a player already exists in the target tournament, that row is silently skipped — existing customizations in the target are preserved, not overwritten.
Add player (inline)
ID always auto-generated (smallest free pNN, checked globally across all tournaments since player IDs are shared). Same name-collision guard as CSV import blocks accidental duplicates.
Inline edit
Name/team/role/credits/overseas save on change.
No duplicate-name check on edit — only on add/import.
Delete player
Confirms first ("cannot be undone").
Blocked with a friendly message if the player is in any saved XI (foreign-key restrict).
Contests
Season / playoff transfer budgets, playoff start match #
Each scoped to one contest. Blank means "unlimited"/"no playoffs". If it's the contest you're currently viewing, changes apply live to your own screen without a reload.
Boosters
Per-contest checkboxes + use-counts for 7 booster types (triple captain, dual captain, wildcard, free hit, overseas-double, US-double, team-double). Unchecked boosters are simply omitted — no separate delete step.
Private Leagues — Create league
Only name is required. Goes live immediately (no activation step), auto-generates a unique invite code.
No duplicate-name guard — the same league name can be created more than once.
+ New Contest
Requires name + contest type. Goes live immediately, public by default.
No duplicate-name guard here either.
Deactivating a contest
There's no per-contest deactivate button in this tab at all — the only way to deactivate contests is Danger Zone's Close Out Tournament, which deactivates every contest for the tournament at once.
Live
Connect
Connects to a live match via CricAPI directly in your browser session — polls every 30 min, stops when the match ends. Ephemeral: nothing about "unmatched" or "fielding not credited" warnings shown here gets written to the Review tab's queues — those only come from the separate server-side poll-cricapi/scrape-scorecard cron.
Link (unmatched player)
Saves a name alias (both locally and to the database) and rescores the match immediately.
Rescore / Save to DB
Recomputes fantasy points from the live scorecard and saves to player_match_stats.
Both functions now dedupe by local player id before saving — previously, two CricAPI names resolving to the same local player (e.g. a fielding-only mention plus that player's own batting line) could crash with a Postgres "ON CONFLICT" error. Fixed to match Finalize's existing behavior; if that happens, the second matching entry is silently skipped rather than merged.
Fetch now
Forces an immediate scorecard fetch outside the normal 30-minute poll interval.
Review
Team code mismatch — Apply Fix
Same underlying remap as Teams' "Apply to existing matches," surfaced here because it's a detected problem, not a proactive setting.
Unmatched Players — Map / Add / Ignore
Map saves an alias for a specific raw name; Add creates a brand-new player and aliases it; Ignore dismisses without crediting anyone. Populated only by the server-side scraper/poll cron — not by the Live tab's own live connection.
Fielding Issues — Credit / Ignore
Credit resolves a detected ambiguous fielding event to a specific player (optionally saving an alias for next time) — internally calls the exact same function as Schedule's manual 🥎 Fielding button.
Recoverable Stats — Credit & rescore / Ignore
For placeholder ("player not found") rows — credit to a real player and cascade the rescore into XI/SL totals immediately.
Duplicate Players — Delete
Only offered for rows with zero usage anywhere (no rosters, XIs, scores, transfers, or live drafts) — safe, direct delete.
Duplicate Players — Keep this, merge other in
Re-checks for collisions live before proceeding (same match scored under both ids, same squad's XI has both, or either is part of a live unlocked draft) — if any collision is found, it explains why and refuses rather than guessing. If clean, repoints every historical reference to the kept id and deletes the dropped one.
Only offered for exactly two-row duplicate groups — three or more duplicates of the same name are flagged for manual SQL review instead.
Danger Zone
Delete Tournament
Permanently removes the tournament row.
Fails safely (does nothing) if it still has matches, players, or contests attached — remove those first, or use Close Out instead. Confirmation spells this out.
Close Out Tournament
Marks the tournament finished (end_date = today, contests deactivated). Shows a live row-count preview per table before you choose what to wipe — reference data (players, teams, profiles) is never touched regardless of selection.
Confirmation lists exactly which tables will be cleared and how many rows, before executing.
Connect a database in the Tournament tab to edit the pool. Local-mode edits are not persisted.
